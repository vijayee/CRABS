CRABS Devtools Demo

Two nodes (alice, bob) in this tab share one WASM module and one devtools overlay panel — the node selector in the panel's tab bar switches between them (the panel slides in/out via the CRABS launcher button). Open a second tab for "two tabs = two peers" mode (ops replicate via BroadcastChannel).

Serve from the repository root, e.g. python3 -m http.server 8000, then open /examples/devtools_demo/.

Alice's node

Ops are HLC-ordered, so every operation from a signer is accepted in sequence. Dislike has no policy, so it is always rejected — rejections show up in the timeline too. Three Flag ops fire the tos_threshold trigger. The State tab is the full state tree (counters, sets, registers, triggers) with diff badges on whatever just changed, and its overview line counts pending schedules; the contact register is ABE-encrypted, so it shows the encrypted marker, never the plaintext address. The Timeline lists every event with layer pills you can filter (op, schedule, trigger, attribute). The "Schedule mint (+60s)" button queues a timed mint: the pending count ticks up as soon as it is submitted, and after ~60s the mint materializes (Timeline + tokens counter) and the count drops back. The "Schedule 3 mints (every 15s)" button queues a recurring mint: three mints materialize over ~45s on the Timeline's schedule layer, then the pending count returns to zero.
