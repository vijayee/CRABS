# Lineage Attestation & Tombstone Key-Stamp Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Close A11-4's residual: stamp lineage attestations AND tombstones with `parent_key_version` at issue time, so a compromised RETIRED parent chain key can no longer mint fresh attestations or fresh dissolutions — its power is bounded to replays of outstanding attestations (TTL-bounded).

**Architecture:** Both canonical bodies gain a u64le `parent_key_version`; the canonical-body version bytes bump (`CRABS_ATTESTATION_FORMAT_VERSION` 0x01→0x02; tombstone tag/version handled in the body builder). Verification binds the signature to the chain entry whose `key_version` equals the stamp (child-side chain lookup; parent-side issuance uses the installed node key and its current `lineage_key_version` — the wedge guard (A11-5) guarantees installed == stashed tip). Old-format bodies FAIL CLOSED (no grandfathering — an un-stamped body would be forgeable by any chain key, voiding the restriction).

**Compat (accepted):** pre-bump attestations/tombstones stop verifying → children re-attest after upgrade; pending stored attestations in existing signed states fail on load/execute (op deserializer tolerates the bytes; verification rejects — fail closed). No state-format bump (the stamp rides inside the opaque attestation bytes; the op serializer caps stay).

**Key code facts (verified):**
- `src/Lineage/lineage.c:119-140` `_attestation_write_canonical_body` — version(1) + string16×4 (parent_id, child_id, user_id, attributes) + not_before(8) + expires_at(8). Shared by create/sign, verify (~:195-215), wire serialize/deserialize (~:240-266).
- `CRABS_ATTESTATION_FORMAT_VERSION 0x01` + `CRABS_ATTESTATION_BODY_MAX 512` (lineage.h:26, 32).
- `attestation_create(parent, out, ...)` (~:142): reads `parent->node_key_valid` + signs via `crypto_sign_operation` — stamp `parent->lineage_key_version` here (parents hold lineage_key_version; A11-5 guard keeps it consistent with the installed key).
- Tombstone: `_lineage_tombstone_write_body(uint8_t* out, size_t cap, size_t* body_len, child_id)` (~:1723, u8 tag + string16); used at :1771 (prepare, signs with parent key) and :1796; verify path in `lineage_op_receive_dissolution` (~:1858, via `lineage_verify_by_parent_key`).
- `lineage_verify_by_parent_key(state, msg, len, sig)` — any-chain-key; the STAMPED lookup variant will be new: `lineage_verify_by_parent_key_version(state, msg, len, sig, version)`.
- Endorsement verify (`attestation_verify_by_lineage_key`, ~:215-235) — iterate chain; with the stamp, resolves the exact entry.
